What you can check in Transitly

For journeys in Zagreb, open the ZET bus and tram map. Find your route, direction and stop, then see the vehicle positions ZET reports live and the next departures.

For train journeys, use the HŽPP departure and arrival search. Choose your stations, date and time. When HŽPP reports a delay, Transitly shows the estimate with the delay included and the original departure time.

What happens behind the map

For Zagreb buses and trams, I start with static GTFS. It contains stops, routes, paths and scheduled times. GTFS Realtime supplies another layer. When the source sends a vehicle position or a departure update, Transitly can match it to the route and show it in the app.

The map labels timetable departures Scheduled and departures with a source update Live. If the source data arrives late, the app's display will lag too. Check the operator's notices for service changes.

The interface uses React and TypeScript. I draw the map with Leaflet and OpenStreetMap tiles, and the server runs on Node.js and Express. A separate train view shows connections and transfers using data from HŽPP. I run the project independently of ZET and HŽPP.
